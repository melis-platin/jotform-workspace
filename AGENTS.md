## Key Rules
- Never override component styles from builder — fix at source in app-elements or design-system
- Never use hardcoded values — always use design tokens
- Builder UI uses `--ds-*` tokens and Circular font from design-system
- Canvas components use app-elements tokens (`--fg-*`, `--bg-*`, `--space-*`, `--radius-*`)
- Icons: builder UI uses design-system Icon (SVG fetch), canvas uses app-elements Icon (lucide/phosphor/tabler)
- Settings tab left navigation must follow the Figma source of truth: **Archieve 27.03.2026**, node `1:307129`. Preserve its 318px panel, spacing, 40px icon area, active/inactive typography, and token-based colors when making future changes.
- Publish tab left navigation must follow the Figma source of truth: **Archieve 27.03.2026**, node `1:307144`. Preserve its 318px panel, four-item layout, spacing, 40px icon area, active/inactive typography, and token-based colors when making future changes. When Push Notifications opens, it must keep this exact Publish navigation and select only the Push Notifications item, as specified by **New Workspace** node `1231:15669`; never replace it with the Settings navigation.
- Publish > Push Notifications > Send Notification must keep the same canvas origin as the Push overview: 36px top padding (`calc(var(--spacing-2xl) + var(--spacing-2xs))`) and an 80px gap after the left panel (`calc(var(--spacing-4xl) + var(--spacing-md))`). Apply these token-based values to both states to prevent layout jumps; do not alter this rule.
- Publish > Push Notifications > Schedule Notification: the SCHEDULE action must remain disabled until both Notification Title and Notification Content have a typed value, as well as a valid send date and time. Never relax this requirement.
- Publish > Push Notifications > Send Notification and Schedule Notification composers must not show `Add Field` controls next to Notification Title or Notification Content. Do not reintroduce field-token insertion in these two composer states.
- Publish > Push Notifications > Send Notification: `SEND TEST` and `SEND NOW` must share the same required-field validation. Keep both disabled while Notification Title or Notification Content is empty, and enable both together as soon as both required fields contain content. Clicking an enabled `SEND TEST` must open the QR test modal, which explains that the app owner can scan the code on their phone to open the app and test the notification.
- Publish > Push Notifications > Audience context menu must show user counts from Publish > App Users role assignments, not device counts; use labels like `Admin - 3 users`, with singular `user` only for count 1.
- Publish > Push Notifications > Target Users selected-role summary must never show a partially clipped badge. Show up to two compact role badges followed by `+N more`; when either of the first two selected role labels is long, show only the first complete badge followed by `+N more` instead. Keep this rule in both Send Notification and Schedule Notification composers.
- Publish > Push Notifications > history-card role tooltips must show no more than three role labels per line. Any fourth and subsequent role belongs on the next line; keep subsequent tooltip rows centered. Apply this identically to Sent, Scheduled, and Canceled cards.
- Publish > Push Notifications > history-card desktop geometry must match New Workspace node `1469:16516`: use a 36px status rail and fixed card heights of 132px (Scheduled), 159px (Sent), and 181px (Canceled). Keep metadata at 12px leading-none; Sent metadata uses 20px item gaps, while Scheduled and Canceled use 16px gaps.
- Publish > Push Notifications disabled state must always take precedence over overview, composer, and sent/scheduled history. When push notifications are disabled, opening Push Notifications must show the disabled screen even when prior notifications exist; never show history until notifications are enabled again.
- Publish > Push Notifications: when scheduled notifications exist, disabling the push notification feature must first open the confirmation modal, show at most two scheduled notification summaries, and show the remaining count in the info band. Only confirmation may change every currently `Scheduled` notification to `Canceled` and disable the feature. `Sent` records must remain `Sent`, and already canceled records must remain unchanged throughout the complete disable → enable cycle. Populate the canceled-by and canceled-at details only for the scheduled records converted to canceled.
- Publish > Push Notifications > Schedule Notification: when Custom is selected in Quick Picks, Send Time must always show the current selectable time rather than a placeholder. Manual date or time changes must switch to Custom without clearing the value the user just selected. Never change this behavior.
- Publish > Push Notifications > Quick Preview notification card styling must stay scoped to the `.push-preview-phone__notification` mockup only. Preserve its native iOS-style system font stack, compact token-based padding/gaps, translucent blurred surface, and title/time/content alignment. The notification title inside `.push-preview-phone__notification-head p` must always be 16px (`var(--font-size-md)`) and use the bold font-weight token. The notification content inside `.push-preview-phone__notification-text` must always be 16px (`var(--font-size-md)`) and use the regular/book font-weight token. The app icon box inside `.push-preview-phone__notification-icon` must always be 40px by 40px (`var(--spacing-3xl)`). Do not apply these styles to notification history cards, permission prompts, or other push notification UI.
- App preset hero headers with transparent mobile top navigation must keep the visible gap from the top nav/avatar row to the hero title equal to the visible gap from the hero CTA to the first page card. Preserve this as one shared layout rule; do not rebalance it with one-off per-preset overrides.
- Live preview phone top header action icons must keep stable sizes and positions across the homepage, inner pages, and opened search/notification states. Search and Push Notifications icons must both be 20px (`var(--space-5)`); keep the same action-group height, gap, padding, and alignment, and never add state-specific spacing that shifts these icons without an explicit design change.
- Navigation Properties desktop header layouts `Fullwidth`, `Contained`, and `Compact` must align page names/nav links next to the right-side search/action group. Keep 12px between page names and the search button, 8px between search and notification buttons, and 12px between notification and the account/auth area — including both logged-in avatar and logged-out Login/Sign up group. Preserve the existing 40x40 action hit areas with 20px icons, and do not apply this rule to the `Left` desktop sidebar layout, mobile, or tablet.
- Live preview search results must show category filters (`All`, `Pages`, `Forms`, `Sign`, `Contents`) only when the current query has results in two or more result categories. If the current query has matches in a single category, hide the filter row entirely and show the matching results directly; do not render an `All` chip plus the single category chip.
- Live preview search in store preset apps must index every visible Product List item as its own product-detail result, just as dynamic List items are indexed. Selecting a product result must open that exact product in the existing product-detail view, not merely navigate to or highlight the Product List. When the product has an image, use it as the search-result thumbnail on the left; fall back to the Product List icon only when no product image exists. Products marked hidden must not appear in search.
- Live preview unread push notification indicators — including header count badges, list dots, and sidebar-avatar dots — must always use the active app color scheme through the canvas `--bg-fill-brand` token, with `--fg-inverse` for badge text. Keep this behavior consistent on empty pages and in phone, desktop notification popover, and `Left` desktop notification page views; never replace it with a fixed color or a neutral/text token.
- Preset app Button components must be text-only. Do not use left or right icons in preset buttons; set both `Left Icon` and `Right Icon` to `none`. This applies to preset page buttons and header action buttons, but does not ban icons in app logos, cards, lists, navigation, or other non-button components.
- Every interactive element shipped in a preset app must have a complete, valid flow. Preset buttons must perform their intended action, page-navigation targets must resolve to an existing related page, dynamic lists must open their generated detail pages, forms must remain submittable, and built-in interactions such as FAQ expansion must work. When loading an older saved preset snapshot, restore any missing required preset actions instead of leaving controls visually clickable but inert.

## Local Dev Server
- When the user asks to start the project locally, run the Vite app with `--host 0.0.0.0` so both `localhost` and the local-network URL are available.
- When the user says they want to share a link with people who are not on the same internet/network, use `ngrok` instead of only the local-network URL.
- For ngrok sharing, read the assigned ngrok host first, then start/restart Vite with `__VITE_ADDITIONAL_SERVER_ALLOWED_HOSTS=<ngrok-host>` so Vite accepts the public URL.
